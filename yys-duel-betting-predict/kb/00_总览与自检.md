## 1. 这套文档解决什么问题

使用者是「**在下注倒计时结束前要做判断的人**」。他面前只有游戏内给的两支 AI 阵容（红/蓝）、每人的面板与御魂。他要据此推断谁赢。

所以本库的一切内容都服从一个判据：

> **这件事会不会影响「自动战斗谁先死」。**

**本库不写**：抽卡概率、觉醒/碎片/材料掉落、御魂副本掉率与速刷阵容、探索/秘闻/结界突破/阴阳寮/式神委派/悬赏封印、皮肤/庭院/外观、斗技段位与匹配规则、逢魔之时/超鬼王等玩法本身。（这些玩法里的**战斗机制**属于收录范围，已在 `06` 收录。）

## 10. skill 内嵌与维护须知（不含任何机器专有路径）

本知识库被设计为**随 skill 一起分发**，因此**不得出现绝对路径、用户名、机器专属解释器路径**。

| 项 | 说明 |
|---|---|
| **分发形态** | `<skill 目录>/kb/` 为知识库副本，与 `SKILL.md` 同级；`kb/data/` 放机器可读数据 |
| **可分发包** | 把整个 skill 目录压成 zip 后改名为 `.skill`（**根目录必须直接是 `SKILL.md`**，不要再套一层目录） |
| **引用规范** | 文档之间只写**文件名**（如 `见 05_御魂与套装.md §4`）；命令示例用 `<skill 目录>/kb/...`、`./lineup.json` 这类**相对或占位路径** |
| **同步方式** | 维护者在**任意一份工作副本**上修改后，把 `*.md` 与 `data/*.json` 覆盖到 `<skill 目录>/kb/` 与 `kb/data/` 即可 |
| **打包前检查** | ① 删掉 `__pycache__/` 等缓存；② 确认包内根目录有 `SKILL.md`；③ 全库搜一遍**绝对路径与用户名**，应为 0 命中 |
| **原始抓取数据** | 抓取中间产物**不要放进分发包**；`kb/data/*.json`（已归一化）才是随包内容 |

**打包/校验最小命令**（跨平台通用，先压 zip 再改名）：

```bash
python3 - <<'PY'
import os, shutil, zipfile
skill = "<skill 目录>"                 # 例如 ./yys-duel-betting-predict
for root, dirs, files in os.walk(skill):
    for d in list(dirs):
        if d == "__pycache__":
            shutil.rmtree(os.path.join(root, d)); dirs.remove(d)
out = shutil.make_archive("yys-duel-betting-predict", "zip", skill)
os.replace(out, "yys-duel-betting-predict.skill")
print(sorted(zipfile.ZipFile("yys-duel-betting-predict.skill").namelist()))
PY
```

> ⚠️ **Windows 注意**：PowerShell 的 `Compress-Archive` 会**拒绝非 `.zip` 扩展名**（直接写 `.skill` 会静默产出 0 字节文件），所以务必**先压 zip 再改名**。
