# 信息索要模板与解析细则

## 0. ⚠️ 式神名去歧义规则（**拿到阵容后第一步就做**）

**SP 阶式神以「修饰前缀 + 本体名」命名，裸名指的是本体（低阶）版本。**

| 裸名（= 本体） | 本体阶 | SP 形态（= 另一个式神） |
|---|---|---|
| **追月神** | **SR** | **流光追月神** |
| 山兔 | R | 梦寻山兔 |
| 座敷童子 | R | 福悦座敷童子 |
| 大岳丸 | SSR | 麓铭大岳丸 |
| 酒吞童子 | SSR | 鬼王酒吞童子 |
| 御馔津 | SSR | 稻荷神御馔津 |
| 千姬 | SSR | 鲸汐千姬 |
| 桃花妖 | SR | 灼华桃花妖 |
| 凤凰火 | SR | 百羽凤凰火 |

**执行要求：**

1. 用户给的阵容里若有「XX + 本体名」的复合名，**先用 `03A_式神全量图鉴.md` §2 的「SP 变体 / sp_of」列确认是哪个**，再去 `03B` 读技能。
2. 若用户只写了裸名（如「追月神」），**按本体（SR）处理并在结论里显式声明**：「按 SR 追月神算，若是 SP 流光追月神结论会不同」。两者技能完全不同，不要混用。
3. 机器可读版：`kb/data/shishen.json` 每个条目有 `sp_of`（SP→本体 id）与 `sp_forms`（本体→SP id）。可用一行脚本自查：
   `python3 -c "import json;d=json.load(open('kb/data/shishen.json',encoding='utf-8'));print([(u['id'],u['name'],u.get('sp_of'),u.get('sp_forms')) for u in d['units'] if '追月' in u['name']])"`

**为什么必须做**：本体与 SP 是两套面板 + 两套技能。以追月神为例，SR 是**鬼火行动条引擎**（`明月潮生` 先机推条 1→4 格 + `清辉月华` 全体攻速增益），SP 是**照君/流光层数 + 集落光免扣火**。认错等于整局判反。

## 1. 一次性索要模板（直接发给用户）

```
我需要下面这些才能算，缺一项都会让结论不可靠（对弈面板不是常规面板，我不能凭记忆补）：

【每场必给】
- 场次时间（如 14:00）
- 红方 / 蓝方 各 5 个式神名（⚠️ 请写全名；SP 与本体同名不同人，如「流光追月神」≠「追月神」）

【每个式神给 4 行】
1) 阵容序号（界面里的 ⑤→③→②→④→① 这种；用来算群攻谁先挨打）
2) 八项面板：攻击 / 生命 / 防御 / 速度 / 暴击 / 暴击伤害 / 效果命中 / 效果抵抗
3) 佩戴御魂：套装名（标明是否成套，如"破势4+暴击2"）
4) 御魂各位置主属性（尤其 2/4/6 号位）

【有就更好】
- 双方"合计加成"那一栏的截图（用来交叉校验我抄的数字）
- 你是不是已经押了、押了多少（我据此调整风险建议）

【被动/机制类式神 —— 请额外确认（不填会漏机制）】
- 若出现「时之隙」体系（卑弥呼 / 时曜泷夜叉姬 / 荒骷髅 / 平将门）、「玄血」体系（龙珏）、
  「布都御魂」（平将门），请把技能原文也发我；这些机制的数值不在面板里，漏了会判反。
- 已知 13 位「纯文字被动」式神（数珠 / 白藏主 / 久次良 / 紧那罗 / 空相面灵气 / 绘世花鸟卷 /
  须佐之男 / 初音未来 / 心友犬神 / 瑶音紧那罗 / 荒骷髅 / 妖刀姬·绯夜猎刃 / 思金神），
  出现时我会去 `03B` 拉技能原文，不劳你手打。
```

## 2. 拿到截图时怎么处理

1. **先把图里的数字逐项抄成表格，回贴给用户确认**，然后再往下算。
   - 对弈面板经常是"御魂配不出来的极限数值"，抄错一位就会算错，确认一次成本很低。
2. 若某格被遮挡/看不清 → **问，不要猜**。写 `?` 并在报告里标 `⚠️ 待核实`。
3. **阵容序号**如果界面没给（只有"阵容顺序"），要明确说明"群攻顺序将按输入顺序推断，可能不准"。

## 3. 数值口径校验（抄完后先自查）

| 检查 | 判据 | 不通过时 |
|---|---|---|
| 速度 | 全场最高速者 = 一速方；合计速度更高的一方通常占优 | 若一速归属反直觉，复核是否抄错 |
| 暴击 | 输出式神 `暴击 < 100%` → 必须按 `1 + 暴击率×(暴伤−1)` 打折 | 在报告里显式写出打折后的期望系数 |
| 暴伤 | 显示值 ≥ 150% | 若 < 150% 基本是抄错（基础就是 150%） |
| 命中/抵抗 | 多为 0 / 15 / 30 … 的整十倍数 | 出现怪值就复核 |
| 御魂 | 是否成套（4+2）；是否出现首领御魂 | 首领御魂在对弈里 2 件套不生效，按"没有 2 件套"处理 |
| **被动/机制** | 是否出现 13 位「纯 prose 被动」式神、时之隙族、玄血、布都御魂 | **必须**在 `skills[].desc` 填技能原文，让脚本告警；报告「未建模项」逐条抄录 |
| 攻击 vs 生命 | 单次核弹型输出：`总攻击 × 系数 × 防御系数` 是否会一击秒杀 | 若账面伤害远超对方生命，属"先手即结束"局，重点转到一速 |

## 4. 写进 `lineup.json` 的对应关系

| 界面字段 | JSON 字段 | 备注 |
|---|---|---|
| 阵容序号 | `pos`（1–5） | **必填**，群攻顺序 `4→1→2→3→5` 靠它 |
| 攻击 / 生命 / 防御 / 速度 | `atk` / `hp` / `def` / `spd` | 直接填界面数字 |
| 暴击 / 暴击伤害 / 效果命中 / 效果抵抗 | `crit` / `cdmg` / `hit` / `res` | **填百分数的数值部分**：界面 85% → 写 `85` |
| 御魂套装 | `souls` | 数组，如 `["破势","荒骷髅"]` |
| 技能 | `skills[]` | 面板换算不出技能，**去 `03B_式神技能全量.md` 查技能名/鬼火/系数** |
| **技能文案原文** | `skills[].desc` | ⭐ **强烈建议填**。把 `03B` 里的技能原文贴进来 —— 只有文字没有参数的被动，靠它才能被脚本识别并告警（见下） |
| 免死 / 无法被治疗 / 减伤 | `passive` | 查 `03_式神数据.md` 的卡片或 `03B` 技能原文 |

> **技能系数怎么填**：`coef` 填**技能说明里那个百分比**（598% → `5.98`），段数填 `hits`。
> 别把段数乘进系数里（曾经踩过：3 段 × 600% 写成 `coef=6.0, hits=3`，结果模拟必赢）。

> **⭐ `skills[].desc` 不是可选项 —— 它是"防漏"机制**：
> 模拟器只读结构化参数，**只有文字、没有数值的被动会被静默丢掉**。把文案填进 `desc` 后，
> 脚本会扫描并输出 `[被动未建模]` / `[机制未建模]` 告警，**报告「未建模项」必须逐条抄录**。
> 已知 13 位「纯 prose 被动」式神（数珠/白藏主/久次良/紧那罗/空相面灵气/绘世花鸟卷/须佐之男/
> 初音未来/心友犬神/瑶音紧那罗/荒骷髅/妖刀姬·绯夜猎刃/思金神）**必须**填；其余式神的被动也建议填。
> 另外 `passive_desc` / `mechanics` / `notes` 三个 unit 顶层字段同样会被扫描。
