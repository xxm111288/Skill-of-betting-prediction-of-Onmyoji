## 1. 最小可用骨架（子类 + monkeypatch，不改基准脚本）

```python

sys.path.insert(0, "<skill>/scripts")
import simulate_duel as B

class UnitExt(B.Unit):
    def __init__(self, spec, side, index, warnings):

B.Unit = UnitExt        # ★★ 关键：基准 Duel.__init__ 用的是模块级全局 Unit，

class DuelExt(B.Duel):

    def apply_damage(self, atk, tgt, dh, ds, crit, w): ...  # 受击叠层
    def lowest_hp_target(self, side): ... # 「强制集火」类印记
```

## 2. 踩过的 6 个坑（照抄结论，别重踩）

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | **没打 `B.Unit = UnitExt`** | 扩展状态字段不存在，机制静默失效 | 子类定义后立刻打补丁 |
| 2 | **召唤物被算进存活数** | 平局兜底判反、`finish()` 结果离奇 | 建一个 `is_londan/summon` 标记，`finish()` 与「双方全灭」判定里都要排除；**召唤物也不推鬼火条** |
| 3 | **概率型/条件型效果不加门控** | 胜率被严重放大 | 先写「触发条件」，再看概率；用日志数触发次数 |
| 4 | **`_qimeng` 这类「追加伤害」按错基数** | 少算一个乘区 | 「等同于**此次攻击伤害** X%」要按**该次技能实际打出的伤害**折算，不能按辅助自己的攻击力 |
| 5 | **「固定伤害/间接伤害」混用** | 算了防御导致偏低 | 固定伤害：**无视防御 + 不会暴击**；间接伤害：**无视防御 + 不触发双方御魂**（`04` §7.1） |
| 6 | **只报点估计、不做交叉验证** | 误把非线性当归因 | 至少 **3 个随机种子**跑同一情景；**只看绝对值会误判**，边际效应在「一方胜率接近 0/100%」时天然很小（天花板效应），**必须做「单独关一个机制」的情景组** |
| **7** | **自己猜 AI 会用哪个技能** | 供火/续航/控制量级全错，且不会报错 | ⭐ 先去 `06` §7.4 查**对弈 AI 权威名单**（信源 A18/A19）。实测差异：食发鬼疑似"会放迷烟"，实际**敌方≥2 且火≥3 必放真实之颜**；童女不是每回合奶，而是**"有人 <60% 生命才放"**；辉夜姬**"幻境剩余 ≤1 回合才续开"**。晚于 2019 的式神没有名单 → 按机制最优近似 + 报告标注 |
| **8** | **把"面板外的战斗内增益"漏掉** | 主输出被低估一个乘区，结论反向 | 面板（对弈竞猜界面给的 8 项）**不含**先机/层数类增益。例：饭笥「储备粮」先机 7 层 = **+70% 攻击 +35% 暴伤**，叠到 10 层还触发**免消耗 9 段大**。**必须逐个 grep 二技能/被动，把"先机获得 N 层"挖出来** |
| **9** | **"百分比攻击加成"的基数搞错**（乘面板 vs 加在式神基础攻击） | 主输出伤害差 20%+，胜率虚高可达 **37 pt** | ⭐ **可以用「面板反解」直接判定**：对弈面板 $=\text{6★基础}\times(1+0.06k)+486$，用界面给的 8 项面板反解 $k$——若十位式神有九位解出整数，说明**加点本身就是一个百分比加成池**，那么战斗内的 `+X%攻击` 必须加进同一池：$\text{总攻击}=\text{基础}\times(1+0.06k+X\%)+486$。公式与实测表见 `01` §2.4。仍属强推断，报告里双向跑并说明 |

## 3. 情景组怎么设（决定报告有没有决策价值）

固定套路：**基准 + 逐机制单独关闭 + 口径存疑项的另一种解读 + 阵容序号反转**。

- **逐机制单独关闭** → 得到「哪个机制值多少个百分点」（本次：闻人翊悬整套 = 25.6pt）。
- **口径存疑项双向跑**（例：万法皆空护盾是「目标最大生命 50%」还是「等于被扣掉的血量」，差一倍）→ 若影响 < 1pt 就在报告里写「口径不影响结论」，省掉一堆口舌。
- **阵容序号整队反转** → 量化「群攻集火顺序」这个用户常常没给的信息到底值多少。
- 用一组模块级开关 `TOG = {...}` + `reset_tog(overrides)` 驱动，避免改代码。

### 3.1 ⭐ 长局的读表纪律（2026-09-30 二轮实战新增）

当两边都是**肉/奶/续航型**、平均要打 **100+ 单位回合**时，裁决之力会叠到 **30 层量级**（增伤 +600%、治疗 −310%）。
此时**每个机制的边际价值都被非线性放大**：那一局逐式神单关，**每个式神都值 12–47pt**。

⚠️ **不要把它念成「这个式神值 40 个百分点」。** 正确的读法是：
> 「**所有拼图同时立着才成立**；任一侧掉一块就翻盘 ⇒ **本局可押注性低**」。

具体做法：
1. 报告里**必须显式写出这个读法**，否则用户会误以为某个式神是"40pt 大腿"；
2. 同时报 **平均单位回合数** 与 **裁决平均行动次数** 两个数——它们直接解释"为什么敏感性这么夸张"；
3. 这种局的推荐档位**默认落到「5 5 开 / 小额」**，除非两侧拼图数量明显不对等。

### 3.2 ⭐ 对弈的「技能满级」前提（每次都要声明）

对弈/百鬼弈的式神**按技能满级处理**。这不是可省略的细节，它直接决定一批结论成不成立：
- 夜溟彼岸花 **Lv5** 才「先机施放赤色凋零」→ 不满级它整条机制不启动；
- 神无月 **Lv4** 才 0 火开大、**Lv5** 才先机给 1 层梦神；
- 云间不见岳 **Lv5** 才先机开御神火界；
- 薰 **Lv3** 才 1 火、**Lv5** 才有先机鸮之守 + 玩耍 +15%。

→ 报告「模型假设」章节**第一条就写它**。

## 4. 报告里必须写进的三块（**不再有「未建模项」章节**）

1. **`ASSUMPTIONS_EXT` 原文照抄**（扩展层的所有近似）。
2. **「机制覆盖清单」**：逐条列出本局出现过的**全部**机制，只允许两种状态——
   - `已建模`：附「怎么建的 / 开关名 / 关键数值」；
   - `信息缺口`：附「① 缺什么（定义·数值·时序）② 已试过的信源 ③ **实盘怎么一眼核对** ④ 对应的双向/多情景区间」。

   **`已建模条数 + 信息缺口条数 = 清单总条数`；出现第三种状态（"未建模""未核实""略"）就等于自检失败，不许出报告。**
   > ⚠️ **守门器的已知盲区**：它判定「纯 prose 被动」靠的是**文案里不含任何数字**（`_NUM_RE`）。
   > 一旦你把技能原文（含 Lv.2–Lv.5 数值）填进 `notes/mechanics`，**绝大部分纯文字机制会被数值掩盖而不报警**。
   > → 所以**清单必须人工枚举**（逐式神 grep 技能原文），不能只依赖脚本告警。
3. **「净值方向」判断**：把 `信息缺口` 按利红/利蓝清点，说明点估计更可能是**低估了哪一方**，
   并给出「若按另一种读法成立」的后果（最好已有对应情景数字）。
